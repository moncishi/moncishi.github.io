# 0001. 使用加权 Token 混合模型折算可用额度与每百万 Token 成本

在真实的大模型使用场景中（如代码辅助、Agent 循环调用），Token 消耗由缓存命中读取、上下文输入以及模型输出共同构成。我们决定不采用官方离散的每项原始标价直接对比，而是基于标准加权模型（如 90% 缓存读取 + 9% 输入 + 1% 输出）统一步骤折算每百万 Token 综合成本与可用配额。这样能消除离散标价造成的感知盲区，给用户一个直观、贴近真实消耗水平的横向对比基准。

## Status

Accepted

## Considered Options

- **直接展示离散标价对比**：直接罗列 Input / Output / Cache 单价表格。缺点是用户完全无法直观理解在真实混合场景下自己的预算能消耗多少总额度，第三方订阅池的价值也无法量化。
- **加权 Token 混合配比折算（选中）**：建立典型加权模型（如 MIX_90_9_1 与 MIX_95_4_1），将输入、输出与缓存读取合并折算为一个综合成本数值与每月理论可用额度。

## Consequences

- 平台的所有核心排名与对比（如 Leaderboard）均建立在加权混合配比的基础上，当用户场景与默认模型偏差极大时需要允许切换配比。
- 单次发生的 `cacheWrite`（缓存写入）被排除在连续配额折算之外，避免对持续性调用额度估算造成波动扰动。
