比价 AI 模型，第一反应是看 input 单价。这个直觉没错，但远远不够。

今天的大模型 API 账单里，至少有三个价格字段在同时起作用：input、output，以及缓存读取（cacheRead）。如果只拿 input 价做对比，相当于用只看裸车价的心态买车——购置税、保险、油耗全被忽略了。

一个更靠谱的做法是给每次调用定义"token 结构"。多数真实工作负载并不是纯问一句答一句：上下文里往往沉淀着大量历史消息、系统提示和工具定义。在共享额度池的计费模型里，这类内容大量命中缓存，价格只有 input 的十分之一甚至更低。

因此我们引入了**加权成本（weighted cost per M）**的概念：给定一个混合比例，比如默认的 90% 缓存读取 + 9% input + 1% output，把三个单价按比例合成一个数。这个数才是"一次典型调用"的真实单 M 成本。你看同一个模型在不同聚合商那里，raw 单价可能差不多，但一加权重，差距立刻拉开。

第二步是把"单位成本"换算成"月度配额"：你充进去的月费（或池内 credits）除以加权单 M 成本，得到的是"这笔钱在这个模型上大约能跑多少百万 token"。注意，月费本身的含义也不同——有的订阅商还收平台附加费，有的完全免附加费，还有的要算进缓存写入费。

第三步是定结构之后再定模型。轻量、高速的模型（比如各种 Flash / Turbo 后缀）单价低，适合做路由的前置过滤；旗舰模型负责真正的深度推理。把工作负载拆开，让不同难度的问题落到不同价位的模型上，整体成本能降一个量级。

最后，别忘了给自己的负载做标注。把生产日志拉出来，按"缓存命中率""input/output 比例""平均上下文长度"打上标签，再用这套方法论重新算一遍。你会发现，对你这种负载最划算的方案，可能和任何一篇"全网最低价"的榜单都对不上——**因为榜单按裸价排序，而你该按自己的 token 结构排序。**
